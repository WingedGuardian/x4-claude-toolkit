<br />[color=#e06666][size=5][b]What Is This?[/b][/size][/color]
<br />
<br />[url=https://claude.ai/code]Claude Code[/url] is an AI assistant by Anthropic that runs directly on your computer. Unlike ChatGPT or a regular Claude chat, it can [b]read your files, run commands, edit configs and execute scripts[/b] -- all with your permission. Think of it as a modding expert sitting next to you who can actually touch your files.
<br />
<br />X4 modding is full of [b]silent[/b] failure modes. A diff patch whose [font=Courier New]sel=[/font] matches nothing validates clean, loads clean, and does nothing. A multi-file change forgets one file and the ware never appears. Another mod quietly overwrites the value you just set. None of it crashes; it just doesn't work, and you find out an hour into a playthrough.
<br />
<br />Most people who try to use an AI assistant for modding spend days wiring up tools, explaining the engine, and building guardrails so it doesn't wreck their install. [b]This toolkit ships with all of that already solved[/b] -- plus a suite of X4-specific tools, written for this environment, that answer questions no off-the-shelf tool can.
<br />
<br />[color=#e06666][size=5][b]New in v2.7 -- the tools tell you WHICH mod moved[/b][/size][/color]
<br />
<br />Every tool here refuses to answer from stale data rather than hand you a confidently wrong number. That was the right behaviour and it was [i]exasperating[/i]: it told you the world had changed, never [b]what[/b] changed. Localising a single updated mod took nine investigative steps.
<br />
<br />[b][font=Courier New]x4modlist changed[/font][/b] now answers it directly, and [font=Courier New]x4modlist snapshot[/font] gives you a baseline to compare against.
<br />
<br />[b]Two things it can now see that it genuinely could not before.[/b] A mod whose [i]files[/i] changed while its [font=Courier New]content.xml[/font] stayed put -- which is the ordinary "edit the file, copy it in" workflow -- was completely invisible: measured on a real 121-mod list, [b]72 of them[/b] had at least one file newer than their own manifest, and every tool reported FRESH while describing a different set of mods. That failed in the unsafe direction. So did a mod enabled or disabled in the game's own mod menu, because toggling rewrites only the profile manifest.
<br />
<br />[i]Also in this release:[/i] a stale-data warning that named a command the release did not actually ship (it ships now); stale warnings that show both fingerprints, so "how far did it move?" is answerable without writing a script; and a set of fixes to the toolkit's own self-check -- the one that deliberately breaks the code to confirm the tests notice. It could not restore the tree if it was killed mid-run, and it silently measured a narrower scope than it reported. While it runs, every tool now warns that it is answering from deliberately broken code, and anything that would write data refuses outright.
<br />
<br />[color=#e06666][size=5][b]New in v2.6 -- ask questions across every file at once[/b][/size][/color]
<br />
<br />[b]BaseX corpus search now ships with the toolkit[/b] (it was internal until now). It indexes the whole corpus -- base game, every DLC, and every installed mod, 36 million nodes -- and answers in about a second the class of question a recursive grep answers [i]dishonestly[/i].
<br />
<br />[b]The specific thing it fixes:[/b] "nothing references this macro" is the most dangerous sentence in modding, because a grep cannot tell [i]this does not exist[/i] from [i]I did not look everywhere[/i] -- and roughly 62% of mod XML lives inside packed archives a grep never opens. So it refuses to print a zero as a finding unless it can state the denominator it looked over, and then says [b]"NEGATIVE CONFIRMED over N of M documents"[/b] with every exclusion named. It also refuses to answer at all from an index that has gone stale, rather than handing you a confidently wrong number.
<br />
<br />Two indexes: [font=Courier New]x4raw[/font] (every file [i]as written[/i]) and [font=Courier New]x4eff[/font] (the merged tree the game actually sees, diffs applied in load order). Use the second for any claim about a live value -- the first will happily quote a vanilla number your modlist overwrote.
<br />
<br />[b]Be honest with yourself about the cost before you start:[/b] it needs Java 17+, about 3 GB of disk, and a one-off build measured in minutes rather than seconds. BaseX itself is bundled (BSD-3-Clause), so there is nothing extra to download. It is entirely optional -- the rest of the toolkit does not need a JVM.
<br />
<br />[i]Also in this release:[/i] a preflight so the first run tells you what is actually wrong -- a missing JVM used to surface as [font=Courier New]BaseX query failed: [WinError 2][/font], blaming BaseX for a missing Java, and an unbuilt index printed a raw error that never once named the build script. And the Linux test failures are fixed (all eight were test-side, not library defects), though Linux remains explicitly [i]not[/i] a supported guarantee -- see the honesty note below.
<br />
<br />[color=#e06666][size=5][b]The Tools -- and What Each One Does For You[/b][/size][/color]
<br />
<br />Eight command-line tools are bundled and pre-wired. No need to stress if it looks like a foreign language--Claude drives them for you as it needs them; though you can also run them yourself. They all read [b]packed[/b] mods ([font=Courier New].cat[/font]/[font=Courier New].dat[/font], VRO included) as well as loose ones.
<br />
<br />[size=4][color=#e06666]x4validate[/color] -- the flagship: catch the silent no-op before you launch[/size]
<br />[list]
<br />[*][b]Every diff [font=Courier New]sel=[/font] is resolved against the real merged tree[/b] (base + all DLC + your enabled mods), so a patch that matches nothing is an [i]error[/i], not a clean pass.[/*]
<br />[*][b]References are checked[/b] -- every ware, macro and [font=Courier New]{page,t}[/font] text id your mod introduces must point at something real.[/*]
<br />[*][b]Completeness[/b] -- compare new content against a vanilla analogue and answer "did I forget a spot?" before the ware turns up priceless and unbuyable.[/*]
<br />[*][b][font=Courier New]--tier b[/font][/b] merges your [i]installed[/i] modlist in load order, so cross-mod patches resolve for real -- and it catches the failure that looks like success: content [b]another mod removed[/b]. (Real case from development: one mod removes a vanilla macro and never re-adds it, orphaning it for six other mods -- 415 engine errors that base+DLC validation calls fine.)[/*]
<br />[*][b]It models the X4 patch rules a naive XML merge gets wrong[/b], each of which otherwise produces a silent no-op: a [font=Courier New]sel=[/font] matching multiple nodes applies [b]nothing[/b] (RFC 5261 -- 236 such ops were silently skipped across one real modlist), [font=Courier New]if=[/font] guards gate an op before the selector, and [font=Courier New]extensions/&lt;target&gt;/&lt;rel&gt;[/font] paths belong to that mod, not the base game.[/*]
<br />[*][b]Validated against the engine, not against itself[/b] -- a test harness replays every patch op X4's own log rejected and requires the same verdict (currently 234/234 agreement, zero false OKs).[/*]
<br />[/list]
<br />[size=4][color=#e06666]x4effective[/color] -- "xEdit for X4": every final value, and who set it[/size]
<br />The effective value of every ware, macro and job across base + DLC + all your mods, with [b]per-attribute provenance[/b] ([font=Courier New]base -&gt; modA -&gt; modB[/font]) in a queryable store. Read one column across everything ("all missiles and their damage"), see the full record, get just the who-set-it chain, list everything a single mod wins, or dump the live merged XML for any path. Stop guessing which mod actually won.
<br />
<br />[size=4][color=#e06666]x4compat[/color] -- what breaks if I install this?[/size]
<br />Collision detection over the effective tree: two mods editing the same node (one silently loses), defining the same registry id, fully overriding the same file, or -- the sneaky one -- a later mod [b]replacing a whole element[/b] and wiping every earlier mod's edits inside it. Candidate mode answers "what would this new mod collide with?" [i]before[/i] you install it.
<br />
<br />[size=4][color=#e06666]x4xref[/color] -- who calls this? who listens?[/size]
<br />A who-calls / who-listens / cue index over every Mission Director and AI script in base + DLC + your mods. "Does anything else react to this event?" in one query, instead of many rounds of grepping for tokens that share no keyword with what you're actually asking.
<br />
<br />[size=4][color=#e06666]x4stats[/color] -- is this balanced against MY game?[/size]
<br />Advisory numeric comparison: how a mod's ware/weapon pricing and stats sit against everything else in [i]your[/i] effective game, including an installed overhaul's rescaled values. Grounds a balance discussion; doesn't pretend to settle one.
<br />
<br />[size=4][color=#e06666]x4similar[/color] -- do I already have this ship?[/size]
<br />Advisory near-duplicate detection: flags a mod's ship as likely "the same ship" you already have under a different name and id, filtered by class and purpose.
<br />
<br />[size=4][color=#e06666]x4modlist[/color] -- triage your whole modlist[/size]
<br />A registry of your installed mods built from what's [b]physically installed[/b] (each mod's own manifest -- folder names lie), cross-checked against your profile. With the optional Nexus API key it pulls upstream versions, update dates, changelogs and status, then sorts everything into lanes: ready / churning / predates your game version / custom-local / dropped-by-the-author.
<br />
<br />[size=4][color=#e06666]x4diff[/color] -- separate your edits from the author's[/size]
<br />Semantic XML diff between two versions of a mod, with multi-baseline support -- built for the "I modified this mod months ago and the author just updated it" problem.
<br />
<br />[size=4][color=#e06666]BaseX corpus search[/color] -- the superweapon: what does this look like across EVERYTHING?[/size]
<br />XQuery over the whole indexed corpus, for the questions that span files rather than living in one: what values does this attribute take across every ship? who references this macro? which mods define a ware nobody produces? It is the only tool here that can back a [i]negative[/i], because it states the denominator it searched. Optional -- needs Java 17+ and a one-off index build.

<br />[color=#e06666][size=5][b]FAQ[/b][/size][/color]
<br />[b]Q: Which game versions / DLC does it support?[/b] The knowledgebase targets X4 v7.x-v9.x and includes the 7.x-&gt;9.0 migration map. All DLC is supported; just tell Claude your version and what you have installed.
<br />[b]Q: Do I need to know how to code?[/b] No. You describe what you want in plain English; Claude does the XML. The tools exist to catch its mistakes as much as yours.
<br />[b]Q: Can Claude break my mods or saves?[/b] The safety hooks should prevent it -- Claude can't write to your reference tree or directly edit .cat/.dat, must ask permission for mod/profile edits, and backs everything up with an audit log. But LLMs are probabilistic; keep your own backups too (X4 saves especially).
<br />[b]Q: Do I have to unpack the base game?[/b] Only for x4validate's full cross-reference power. You can start without it; setup walks you through unpacking with XRCatTool when you're ready.
<br />[b]Q: Does it work with VRO / big overhauls?[/b] Yes -- and that's rather the point. The tools read packed mods, so an overhaul's rescaled values show up in the effective tree, in balance comparisons, and in collision checks.
<br />[b]Q: "jq not found"?[/b] Run [font=Courier New]winget install jqlang.jq[/font] and restart Claude Code.
<br />[b]Q: How do I update the toolkit?[/b] Download the new version and re-run the installer (or extract over the old one). Your knowledgebase additions are preserved.
