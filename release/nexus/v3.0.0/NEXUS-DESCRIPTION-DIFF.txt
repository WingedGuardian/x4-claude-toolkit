 Most people who try to use an AI assistant for modding spend days wiring up tools, explaining the engine, and building guardrails so it doesn't wreck their install. [b]This toolkit ships with all of that already solved[/b] -- plus a suite of X4-specific tools, written for this environment, that answer questions no off-the-shelf tool can.
 
+[color=#e06666][size=5][b]New in v3.0 -- ask the running game, and a guard that turned out to be walkable[/b][/size][/color]
+
+[b]The toolkit can now query a live game session.[/b] It ships a small optional game extension that opens a channel to X4 while it is running, so "what does the engine actually say this ship's hull is, in my save, right now" becomes a query instead of an inference. Every other tool here reasons about what the merged tree [i]should[/i] produce; this one reads what the engine [i]did[/i] produce -- and the two disagreeing is precisely the case worth finding. It is also how several of the defects fixed in this release were caught.
+
+[b]If you also mod Skyrim: this is our much weaker [url=https://www.nexusmods.com/skyrimspecialedition/mods/181326]DevBench[/url].[/b] alandtse's DevBench is the mature version of this idea -- a proper programmatic interface to a running Skyrim over MCP or HTTP, which runs console commands and reads their output back, calls functions and gets return values, and drives scripted test scenarios in the live game. [font=Courier New]x4live[/font] does considerably less than that today: it reads live state, and that is most of what it does. It is aimed in the same direction, it is under active development, and DevBench is the standard we are measuring it against. If you mod both games, go and look at it -- it is the better tool, and it isn't ours.
+
+[b]The honest half of a major version.[/b] The safety guard that inspects every command was walkable. A delete aimed at the game folder, wrapped in one particular shell form, came back ALLOWED -- while the same delete written plainly was correctly blocked. One line was doing a substring search where it meant whole-word matching. That was live while 996 generated test cases, 82 mutation probes and 388 unit tests were all green, because the generator built to find exactly this could not produce that shape by construction. An instrument's blind spot is usually written into its own design.
+
+Fixed, and the generator rebuilt to vary the [i]shape[/i] of a command rather than replay the bugs we already knew about. The fix was then re-checked against 13,503 real commands from actual sessions: [b]8 verdicts changed, every one stricter, none looser[/b] -- including two that had been quietly allowing a recursive delete inside the game install.
+
+[b]Also fixed, and this one is a data bug rather than a reporting one:[/b] the merged tree was discarding base-game content for DLC files, so a question as ordinary as "what rooms exist" came back with the wrong answer.
+
+[b]Protection for the files you cannot get back.[/b] During development the toolkit's own hand-built mod registry was destroyed four times in twelve days -- never once by a decision, always by a command that ran, resolved to a real path, and met nothing in the way. Irreplaceable files are now marked read-only (measured over 14 write methods, each paired with a control proving it still works when unlocked: [b]11 blocked on Windows, 9 on Linux/macOS[/b], with the gaps documented rather than glossed), a session-start check refuses to continue if one has been emptied or deleted, and the registry save is atomic and refuses to shrink.
+
+[b][color=#e06666]Note:[/color] the command guard now requires Python[/b] -- already needed by the bundled tools. Without it the guard [i]asks[/i] rather than silently allowing.
+
+[color=#e06666][size=5][b]Also new since v2.7 -- 2.8 and 2.9 never came to Nexus[/b][/size][/color]
+
+[b][font=Courier New]x4save[/font] -- read a savegame, and say what removing a mod would silently cost you.[/b] Saves are gzipped XML and far cheaper to query than their size suggests. Two findings worth having even without the tool: a mod's presence in a save's patch block is [i]not[/i] a record of what loaded -- it is the save-baked set, which was 3 of 121 mods on a real list -- and removing a mod leaves no loud dangling references, because the engine deletes the orphaned content silently. In one measured case 37 macros vanished and the log carried a single line about it.
+
+[b][font=Courier New]x4diff --base[/font] -- three-way diff.[/b] Built for "I edited this mod months ago and the author just updated it": it separates your changes from upstream drift, instead of showing you one merged wall of differences.

+[b]A patch that patches another mod is finally checked.[/b] Nested cross-mod script patches were validated by nothing at all, and a mod shipping its own [font=Courier New]md/[/font] or [font=Courier New]aiscripts/[/font] used to read as a clean pass.

+[b][font=Courier New]x4modlist tracked[/font][/b] -- what your Nexus account follows, set against what you actually have installed.

+[size=4][color=#e06666]x4debug[/color] -- what did the ENGINE actually complain about?[/size]
+Turns X4's own [font=Courier New]debug.txt[/font] into a triage: every error line bucketed and attributed to a mod, with the buckets required to sum to the input so nothing is quietly dropped. Crosscheck mode compares what the engine skipped against what the validator predicted, [i]per item[/i] -- and "the engine hit it but we never predicted it" is a validator blind spot, which is how a fair number of the fixes in this changelog were found.
+
+[size=4][color=#e06666]x4save[/color] -- what would I actually lose if I removed this mod?[/size]
+Reads a savegame and reports what is baked into it. Worth having because the failure mode is silent: the engine deletes content orphaned by a removed mod without complaining, so the save looks fine right up until it doesn't.
+
+[size=4][color=#e06666]x4live[/color] -- ask the running game[/size]

Entirely optional -- and it is the only part of the toolkit that puts an extension in your game folder.
