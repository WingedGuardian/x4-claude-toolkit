# Individual tool audit — 2026-10-01

Historical baseline report. Repairs authorized subsequently are tracked separately
in [the 2026-10-02 follow-up](2026-10-02-tool-fixes.md); the evidence below is preserved.

## Scope and conclusion

Hands-on, audit-first review of the individual tools on toolkit commit
`aa57efc4a4c40d39d7bc80574935b0e45e63fe56`, in branch
`session/tool-audit-20261001`. The worktree began at `b7ceb2a` and was advanced
before these findings were rechecked. No tool implementation was changed.
Generated agent files and the parallel harness/generalization work are outside scope.

Eight distinct defects are reproduced below. The most consequential are false
negative certificates in BaseX and xref, and the legacy local deploy helper's
write containment failure. Valid-input controls generally work. A passing unit
suite does not cover these inputs: new adversarial CLI exercises expose them.

Confidence percentages describe confidence in the stated, bounded finding,
not the probability that a proposed patch will be safe. No fixes were implemented
or tested, so this report does not assign confidence to unbuilt changes.

## Confirmed defects

### TA-01 — BaseX `attr` accepts query syntax and certifies a filtered zero

**High; confidence 99%.** `ask.py attr 'name[false()]' --db x4raw` returns rc 0
and `NEGATIVE CONFIRMED over 12 of 12 documents (complete)` on the scratch
database. `attr name` finds existing values. The argument is documented as an
attribute name but interpolated into XPath without name validation.

Root cause: `tools/basex/ask.py:q_attr` (line 508) inserts the argument into
`//@{attr}` and `//*[@{attr} = $v]`; the scope check at line 886 is applied only
to `xq`. It assumes the internally generated `attr` query is safe although
part of it comes directly from the user. Reproduced on both real scratch
databases too; x4eff lists its exclusions but still certifies the filtered zero.

**Change to consider:** validate the attribute name before constructing XQuery,
with explicit supported namespace semantics. Reject XPath syntax as input.
Regression: valid `name`, legitimate namespaced names if supported, malformed
names, and this filtering expression. Evidence: `basex-fixture-invalid-attribute`.

### TA-02 — BaseX misses conditional positional predicates

**High; confidence 99%.** The full query
`collection('x4raw')//cue[@name='AuditCue']` finds one cue. The query
`collection('x4raw')[if (true()) then 1 else 2]//cue[@name='AuditCue']`
finds zero but returns rc 0 and the complete-database negative certificate.
It searched only the first document. The `[1]` control returns rc 4 and
withholds the certificate as intended.

Root cause: `_scope_tokens` / `_NUMERIC_PRED` recognize simple numeric predicates
and selected numeric function calls, not conditional expressions that return
a number. The source's listed residuals do not describe this case.

**Change to consider:** conservatively withhold certification for unproved
predicate expressions, or use a parsed/validated restricted query grammar.
Adding just this spelling to a regex will leave equivalent numeric expressions
unexamined. Evidence: `basex-fixture-cue-positive`, `basex-fixture-positional-if`,
`basex-fixture-positional-simple`.

### TA-03 — xref accepts damaged TSV rows or crashes on them

**High; confidence 99%.** Removing the trailing empty field from the known
`find_station` row in an otherwise fresh generated index silently drops it.
`who-calls find_station` returns rc 0 and describes a "real negative" over
the remaining three rows. The original index finds the action. A seven-column
row with `line=not-an-integer` instead produces an uncaught `ValueError`.

Root cause: `_xref.py:215` ignores rows whose length is not seven and directly
converts the sixth field to `int`. It does not validate the header. Source
freshness does not establish the integrity of the generated TSV itself.

**Change to consider:** validate the entire index before answering, refuse
malformed headers/rows with a path and line number, and consider an artifact
digest stamped at build time. Evidence: `fixture-truncated-xref-false-zero`,
`fixture-corrupt-xref-index`, positive fixture xref queries.

### TA-04 — x4save does not catch invalid DEFLATE streams

**Medium; confidence 99%.** A gzip header followed by an invalid DEFLATE block
makes both `info` and `check` emit Python tracebacks and exit 1. The module
defines unreadable-save handling as rc 2. The valid gzip fixture and real save
both work.

Root cause: `_savecli.py:71` and `:95` catch `OSError`, `EOFError`, and
`gzip.BadGzipFile`, but not the `zlib.error` raised by this compressed stream.

**Change to consider:** translate this decompression exception through the
existing unreadable-save path; test malformed DEFLATE, truncated streams,
bad headers, and valid saves. Evidence: `fixture-save-invalid-deflate-info/check`.

### TA-05 — x4effective crashes on a corrupt SQLite store

**Medium; confidence 98%.** `x4effective --db not-sqlite.db ls ware` with a
plain-text file emits an uncaught `sqlite3.DatabaseError` and exits 1.
The valid fixture store supports the same command.

Root cause: the read-only connection can be opened before SQLite reads a
database page; the later command executes SQL without a boundary handler for
unreadable/incompatible stores. `_effective.py:_connect`, `_effectivecli.py:main`
and `_cmd_ls` show this path.

**Change to consider:** report a non-answer with rebuild guidance for corrupt
or incompatible stores. Keep SQL semantic errors distinct. Evidence:
`fixture-corrupt-effective-store`.

### TA-06 — old x4cat `init` succeeds with an empty template

**Medium; confidence 99%.** Local x4cat 1.2.6 has an empty
`templates/extension_poc` submodule directory. `init audit_empty_template -o
<fresh scratch directory>` returns rc 0 and `Created project`, but creates no
`content.xml`, README, or MD script. Nineteen scaffold tests fail for missing
generated files; two additional test failures are Windows symlink privilege
limitations, not tool defects.

Root cause: `_init.py` treats `is_dir()` as proof the template is present and
silently skips every missing template file. An uninitialized submodule directory
therefore prevents its missing-template fallback while satisfying no contract.

**Change to consider:** validate required template files before writing or
reporting success. Do not make network access the only recovery. Evidence:
`x4cat-init-empty-template` and `x4cat-tests`. This tool lives outside the toolkit
repository; changing the shipped suite would not fix that installed copy.

### TA-07 — legacy local deployer's assertions disappear under `-O`

**High safety impact; confidence 99%.** A normal-interpreter scratch run refuses
an unowned mod. With `python -O`, the same helper overwrites a destination whose
manifest ID differs from the source, prints "guard ok", and returns success.

Root cause: ownership, source/destination, and manifest guards in local
`dev/_tools/deploy.py:104` onward use `assert`. Python optimization removes them.
The explicit retired-mod check survives; the other guards do not.

**Change to consider:** use explicit checks for all safety conditions, following
the retired-mod check's existing example. Evidence: `legacy-deploy-normal-guard`,
`legacy-deploy-optimized-guard`.

### TA-08 — legacy local deployer follows destination junctions

**High safety impact; confidence 99%.** In a disposable fixture, a destination
mod's `linked` directory is a junction to a scratch directory outside that mod.
Deploying an owned mod overwrites that external directory's `payload.txt` and
returns `RESULT True`. This requires no Python optimization.

Root cause: destination checks use lexical path relationships. The copy phase
does not reject junctions or resolve each destination against the intended mod
root. Its verification follows the same junction and confirms the escaped write.

**Change to consider:** refuse reparse-point components before copying or deleting,
verify resolved paths remain inside the intended destination, and preflight the
whole plan before mutations. Evidence: `legacy-deploy-junction`. All fixture
paths, including the "external" victim, were inside the audit worktree. The
actual development/deployed mods were never used for an apply operation.

## Feature gaps supported by this run

- BaseX attribute output is unbounded: real `attr name` returned 113,192 items,
  about 3.2 MB, in 74.6 s. Add output limits/pagination with full totals; avoid
  implying every discovery query takes about a second.
- A source freshness stamp does not establish generated artifact integrity.
  TSV header/row validation and artifact hashes would materially improve xref.
- Current successful/refused/degraded codes are useful but do not provide one
  consistent structured result across tools. Any audit caller must inspect
  output and scope, not equate an accepted exit code with functionality proved.
- Ship similarity deliberately excludes 98 under-specified vectors in this
  real run. Its warning is accurate; additional meaningful stats need separate
  design and engine evidence. This is an announced limitation, not a defect.

## Safety, provenance, and reproducibility

The harness writes within the separate audit worktree, plus newly allocated
system-temp pytest directories to avoid Git ancestor contamination. Registry and
profile enable decisions are copied. BaseX DBPATH/REPOPATH/WEBPATH are pinned to
scratch. Production references, extension XML, catalogs, logs, and saves are only
read by the authorized exercises. There was no production deployment or modlist,
save/profile edit. Engine and Nexus end-to-end behavior remain unverified.

Before/after snapshots cover metadata for 24,878 recorded XML/XSD/catalog/save
files and hashes for 50 small state files. This is deliberately a bounded claim:
they do not hash all content or cover every game-root archive, workshop/profile
extension, or nested production BaseX file. They cannot prove universal
immutability or enforce safety against arbitrary code. Final comparison is in
the summary artifact. The initial comparison found zero metadata/hash differences.
A separate, expanded comparison over the final control interval recorded
526,564 protected-file metadata entries and also found zero differences. That
later baseline does not extend the original interval or prove content equality
for every file.

Commands retain raw stdout/stderr and ledger records in untracked `audit-output/`.
Newer records carry exact toolkit source revision, run ID, and driver.py hash; repeats
preserve earlier logs under `logs/history/`. Earlier records lack those fields.
External deployer and x4cat scaffold source hashes are recorded separately in
the final summary, collected at summary time rather than before execution; the
toolkit revision does not identify those external files. The x4cat hash identifies
the copied source actually exercised.
Withdrawn harness expectations include collision rc 0, shipless similarity rc 0,
BaseX shell path conversion, archive file-as-directory/default catalog prefix,
attempts to query a database during its build, and a BaseX fixture rebuild
overlapping fixture generation (rerun sequentially with fresh coverage). The
intentional `audit-timeout-control` CHECK verifies terminating only a newly
created sleeping audit process and preserving its logs; it is not a tool defect.

The report and harness received independent review. Factual coverage/provenance
corrections were incorporated, then the suite, 11 CLI/47 subcommand surface,
controlled defect probes, real-data tool chain, BaseX queries, archive roundtrip,
legacy deployment probes, dependency and packed-content controls were rerun.
All eight defect families remain reproduced; positive/refusal controls pass.

See `tools/x4validate/audit/README.md` for rerunning. These scripts are an audit
instrument, not a new supported CLI or a production deployment mechanism.

## Recommended implementation order

1. Correct TA-01/02/03 before relying on new negative certificates.
2. Retire or repair the local legacy deploy helper (TA-07/08); its safety claims
   do not hold for the reproduced inputs.
3. Fix unreadable-save/store handling and required-template validation.
4. Add bounded BaseX output and structured result contracts where useful.

Each implementation needs independent review followed by fresh end-to-end
controls. This audit proves the failures; it does not prove a proposed fix.
